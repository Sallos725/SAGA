# ADR 0011: Scenario Cards, Grounded Natural-Language Intent, and Free-Action Adjudication (A1 Slice 1)

Date: 2026-11-27
Status: **Accepted (M2)**

## Context

Under M1, new worlds still inherit their initial actors, NPCs, flags, and map from the
pinned rulebook's `example_world`. That couples setting/campaign content to rulesets. In
addition, players typing natural-language movement (`"북쪽으로 간다"`) or creative free
actions not listed in the rulebook (`"밧줄을 잘라 샹들리에를 떨어뜨린다"`) need a safe,
replayable way to resolve actions without letting LLMs mutate state or re-roll on
regeneration.

## Decisions

### 1. Scenario card contract (`ScenarioSpec` v1)

- `saga_trpg/rulebooks/scenarios.py` defines `ScenarioSpec` (`schema_version: 1`, closed
  schema) holding initial `actors`, `flags`, `quest_state`, `simulated_time`, optional
  `ruleset_id`, optional `map` (authored with `map_problems` + 200-room cap, or seeded
  generator), and optional `narration`.
- `build_scenario_world` validates the scenario against the pinned `RulebookSpec`
  (ruleset compatibility, actor HP bounds, closed item keys, known conditions, valid map
  exits and placements) and deterministically constructs genesis `WorldState`.
- Scenarios can be delivered via:
  - `POST /worlds/{world_id}` (`CreateWorldRequest.scenario`),
  - `HostTurn.scenario` (protocol v4 only; pins initial world on creation and is ignored
    once the world exists),
  - RisuAI module data entries (`saga:scenario:<id>@<version>:<sha256>`, never-matching
    regex `(?! )`, zero scripts) generated by `python -m saga_trpg.rulebooks scenario-module`.

### 2. Grounded natural-language intent (`rulebook_grounding.py`)

- `intent_context_for` exposes only the player's current room exits (with Korean/English
  direction hints) and actor roster—never unseen rooms or other actors' locations
  ([ADR 0009](0009-locations-and-map-movement.md)).
- `ground_proposal` strictly validates proposed events against the pinned rulebook's
  closed payload models, current room exits for `map_move`, and committed actor roster for
  `target_id`.
- `OpenAICompatIntentTool` records proposals once on the durable tool tape
  (`risu-openai-intent-v2`) and safely degrades malformed/unsupported LLM output to
  `narrative_turn`. Untrusted `client_proposal` on `POST /v1/saga/turn` is strictly
  rejected with 422 before creating a world or mutating state.

### 3. Free-action GM adjudication (`adjudicate_action`, A1 first slice)

- `ADJUDICATE_ACTION_KIND = "adjudicate_action"` is a reserved runtime event with closed
  payload `AdjudicateActionPayload` (`description`, `mode`: `auto_success | check |
  impossible`, optional `difficulty` 1..100 for `check`, `modifier` -20..20,
  `advantage`/`disadvantage` on `1d20`, allow-listed `dice_expression`: `1d20 | 2d6 |
  4d3-8`, optional `ability`, `stakes`, `reason`).
- `RuntimeEngine` validates the actor and payload, rolls deterministically via `DicePort`
  when `mode == "check"`, computes `RuleResolution` (`success` / `failure`), and records
  deterministic `facts` and `trace`.
- In this first slice, `adjudicate_action` produces **zero direct state patches** (HP,
  inventory, and map remain untouched unless explicit rulebook actions follow), satisfying
  the A1 safety boundary in [TRPG_FEATURE_REVIEW.md](../TRPG_FEATURE_REVIEW.md).
- Because the adjudication parameters and dice outcome are committed to the journal before
  narration, regenerating a reply never alters difficulty, stakes, or dice results.

## Consequences and invariants

- Existing v1–v3 protocols, bundled rulebooks, storage v2 schema, and RuleCheeseBench
  command grammars remain unchanged.
- `adjudicate_action` is not part of `command_verbs`, so benchmark scoring is unaffected.
