## Changed

- Implemented `SQLiteWorldRepository` and a transaction-bound journal adapter. The debug API
  now uses the persistent repository at `$TRPG_DATA_DIR/worlds.sqlite3` rather than an
  in-memory registry. Worlds retain genesis state, seed, and ruleset/runtime versions.
- Committed entries and periodic snapshots are saved atomically. Writes acquire a SQLite
  transaction before idempotency lookup or dice execution and expose results only after commit.
- Added snapshot recovery, strict full/prefix replay, branch creation, branch metadata, and
  history APIs. Forks copy immutable committed prefixes and preserve roll records and provenance.
- Runtime retries resolve event ids and idempotency keys before rules/tools. Conflicting
  proposals are rejected, including JSON boolean/number differences. Old-result reads do not
  rewind current state. Generated ids on new branches use a branch prefix.
- Fixed process-dependent hashing of condition sets, unchecked replay ordering/hashes/trace,
  unsupported state versions returned by rules, and JSONL cache publication before a write.
  Replay validates model versions, contiguous sequence, world identity, unique identities within
  the replay segment, before/after state hashes, and required traces.
- Event envelopes reject extra fields and empty ids. Journal schema version is 1, runtime
  compatibility version is `0.2.0`; state/event schema version remains 1. `JournalPort` adds
  idempotency-key lookup. Public schemas are generated by `scripts/export_schemas.py`.
- Documented the storage contract, HTTP surface, compatibility policy, retention, and failure
  behavior in [PERSISTENCE.md](../PERSISTENCE.md). Updated README, architecture, task tracking,
  and handoff pointers. Memory, dice, and narrator port contracts remain unchanged.
- Cleared the two original lint findings and four original formatting findings with small
  formatting-only changes. NMOS/MCP adapter behavior was not implemented or changed.

## Trade-offs and risks

- SQLite was chosen under the handoff's explicit allowance. Standard-library transactions
  provide atomic event/snapshot commits and serialize duplicate requests across processes
  without another service or dependency. Writes currently serialize across the whole database;
  a slow tool holds that write transaction. This is a correctness-first local deployment slice.
- Entries contain full post-event states; snapshots are saved at genesis, every 50 new events
  by default, and each fork. All entries/snapshots are retained. Prefix copies and unpaginated
  history responses are simple but can become expensive for large campaigns.
- Snapshot recovery validates the snapshot boundary and subsequent chain. Full replay is
  required to audit older history. Hashes are not a tamper-proof signature of all event fields.
- Committed retries never reroll. External tools can nevertheless execute before a failed
  commit; exactly-once external side effects across that failure window are not guaranteed.
- Unsupported storage/ruleset/runtime versions fail closed. No automatic migration or legacy
  JSONL import is supplied. Future migrations must preserve originals and prove replay equivalence.
- Standalone JSONL remains single-writer and cannot recover torn tails automatically. A write
  or fsync error can leave uncertain disk contents; inspect/reopen it before retrying. The HTTP
  host uses SQLite instead. Legacy unversioned JSONL hash adoption is not automatic.
- The existing generic rules still accept unhandled kinds as traced no-ops; ruleset-specific
  closed payload validation and intent interpretation remain roadmap work. Debug endpoint
  authentication/multi-tenant isolation was not changed.

## Architecture self-review

- Deterministic engine, replay, hashing, and domain changes add no filesystem/network I/O,
  clock reads, or unseeded randomness. SQLite I/O lives in the outer storage adapter. The
  existing JSONL I/O class remains separate from deterministic execution logic.
- Rules run only through `RuntimeEngine`; dice only through `DicePort`. Recovery, branch
  creation, journal reads, and rerender do not invoke tools. Each committed record has its
  event id, trace, state hashes, and recorded rolls.
- Narration uses detached committed records and cannot reach authoritative persisted state.
  No LLM mutation path, NMOS internals, secondary vector store, or new external service was added.
- Seed and journal preservation keep replay/benchmark inputs reproducible. Production
  orchestration and benchmark scaffolding remain separate.
- No secrets or environment files were changed. No files/history were deleted and no commits
  were created. The repository was originally unborn and all scaffold files remain untracked.
