# 외부 TRPG 플러그인을 참고한 기능 도입 검토

검토일: 2026-10-09. 상태: **도입 후보 제안**. 대상: SAGA와 NMOS의 제품 기획 및 후속 설계.

TRPG의 자유도, 플레이어 선택권, 진행 속도, 장기 캠페인의 일관성을 기준으로
외부 RisuAI TRPG·기억 플러그인에서 참고할 기능을 분류한다. 현재 SAGA에 쉽게 맞는지만으로
가치를 판단하지 않는다. 자유행동 판정, GM 정정, 선택을 보존하는 자동 진행은
진행 방식의 변경을 검토할 만큼 가치가 있다. 판정 카드와 장면 인물 보드는
현재의 판정·기록 원칙을 유지하면서 먼저 추가할 수 있다.

아래의 도입 형태와 수용 시나리오는 제안이다. 이 문서는 기존 ADR을 대체하거나
구현·배포를 승인하지 않는다. 채택 시 의미가 바뀌는 항목은 별도 ADR과 범위가 필요하다.
참고 사례에서 관찰한 동작과 우리가 도입할 형태를 구분하며, 원본 코드를 그대로 복사하는
것을 전제로 하지 않는다.

## 분류 기준

- **A — 우리 기능을 고쳐서라도 가져올 가치가 있는 기능:** 진행, 판정 권한,
  상태 표현 또는 작업 흐름의 변경을 감수할 가치가 있다. 기존 구조와의 충돌은
  설계할 문제이며, 그 자체로 기각 사유가 되지 않는다.
- **B — 우리 기능을 안 고치고 가져올 가치가 있는 기능:** 현재의 판정·기록 의미를
  유지하면서 표시, 작성 지원, 기억 활용 또는 검수 기능을 더할 수 있다.
  코드 변경이나 인터페이스 확장이 전혀 없다는 뜻은 아니다.

## A 기능 변경을 감수할 도입 후보

### A1 자유행동에 대한 GM 판정

**플레이 가치:** “밧줄로 샹들리에를 떨어뜨린다”, “자물쇠 대신 경첩을 부순다”처럼
명령 목록에 없는 시도가 플레이 가능한 행동이 되어야 한다.

**참고 사례:** 탐험 장치의 고정된 조건을 읽고, 목록에 없는 접근법도 물리적으로
가능한지 해석한다. 해석은 지도·난이도·전리품·성공 결과를 변경하지 않도록 제한된다.

**도입 제안:** 행동의 가능성, 적용 능력, 난이도, 비용, 성공·실패의 결과를 먼저 정하는
판정 준비 단계를 둔다. 어떤 행동은 자동 성공이고 어떤 행동은 굴림이 필요한지,
애매한 상황에서 누구에게 선택을 돌려줄지도 정한다. 매번 사용자 확인을 요구하는
것은 목표가 아니다. 확정한 판정 조건과 결과를 이후에도 설명할 수 있어야 한다.

**수용 시나리오:** 기존 목록에 없는 타당한 해결법은 실제 판정으로 이어진다.
불가능한 시도는 이유를 설명한다. 실패 결과를 본 뒤 같은 행동의 난이도·비용을
유리하게 바꾸지 않으며, 새로운 시도와 단순 요청 재전송을 구별한다.

### A2 설정을 플레이 자료로 전환

**플레이 가치:** 캐릭터 카드와 로어북을 가진 사용자가 모든 NPC·기술·물품을
다시 수작업으로 작성하지 않고 캠페인을 시작하고 즉흥적으로 확장할 수 있다.

**참고 사례:** 로어에서 인물 후보를 찾고, 행동 준비 중 필요한 인물을 등록하며,
준비된 자료를 재사용한다. 같은 이름의 적 여러 명과 별칭도 구별하려는 경로가 있다.

**도입 제안:** 설정에서 생성한 초안과 플레이에 확정한 정의를 구분한다.
원문에 있는 값, 계산한 값, GM이 임시로 정한 값을 표시한다. 누락된 숫자를
추정할 수 있는 범위와 재사용·재작성 조건을 정한다. 플레이 중 새로운 대상을
등록할 수 있어야 하며, 기존 인물을 다른 이름으로 다시 만들지 않아야 한다.

**수용 시나리오:** 숫자가 없는 NPC도 선택한 룰에 맞는 초안으로 준비할 수 있다.
동일 NPC를 다시 만나면 확정된 상태를 사용하고, 동명이인과 여러 개체는 구분한다.
원문 설정이 바뀌면 기존 진행 상태를 덮어쓰지 않고 변경 차이를 검토한다.

### A3 GM 정정과 장면 정산 및 대안 분기

**플레이 가치:** 누락된 보상을 지급하고, 계산 실수를 고치고, 오해한 장면을
되돌릴 수 있어야 캠페인을 계속할 수 있다. 정정은 정상적인 GM 기능이다.

**참고 사례:** 이전 서술과 저장된 결과를 비교해 보완 작업을 제안·실행한다.
장면 보정에는 서술상 처치된 적의 사망·보상 정산이 포함된다. 재생성은 이전 답변의
부모 상태를 선택하는 경로가 있으며, 수동 편집을 복원할 때 충돌을 구분한다.

**도입 제안:** 다음 세 작업을 플레이어가 구분할 수 있게 한다.

| 작업 | 의도 | 기록에 미치는 영향 |
| --- | --- | --- |
| 묘사 다시 쓰기 | 같은 사건을 더 적절하게 서술 | 확정된 판정과 결과 유지 |
| 다른 선택으로 진행 | 과거의 선택을 바꿔 새로운 전개 탐색 | 지정한 지점에서 대안 분기 생성 |
| GM 정정 | 누락·오판·설정 오류 수정 | 대상, 이유, 변경 내용을 가진 정정 기록 추가 |

서술상 사건을 확정하는 기능도 명시적인 GM 판정으로 설계할 가치가 있다.
자동 적용 가능한 누락 정산과 사람의 판단이 필요한 결과 변경을 구분한다.
응답 모델이 쓴 문장만으로 기존 실패를 성공으로 바꾸는 것은 제안 범위가 아니다.

**수용 시나리오:** 빠진 보상은 한 번만 정산된다. GM 정정과 이전 판정의 관계를
확인할 수 있다. 대안 분기 후 원래 전개를 다시 선택할 수 있으며, 후속 의존 사건과
충돌하는 소급 정정은 충돌을 표시한다. 재시도 자체가 재굴림을 만들지 않는다.

### A4 플레이어 선택을 보존하는 자동 진행

**플레이 가치:** 적·동료의 턴을 진행하려고 매번 “계속”을 입력하지 않아도 된다.
의미 없는 반복을 줄이면서 중요한 행동·반응은 플레이어가 결정한다.

**참고 사례:** NPC 턴을 이어 처리하고, 지휘관 모드·행동 모드·빠른 전투·결과만
정산하는 옵션을 제공한다. 선택·반응·구원 대기와 처리 한도를 진행 경계로 사용한다.

**도입 제안:** 사용자에게 위임받은 행동과 직접 선택할 행동을 구분하는 진행 제어를 둔다.
NPC 처리, 사용자 입력 대기, 중단, 재개를 지원한다. 전투 결과만 표시하더라도
실제 소모·피해·보상은 같은 규칙으로 계산하고 기록한다. 행동 게이지 방식은 선택적인
룰 기능이며, 자동 진행 도입의 필수 조건은 아니다.

**수용 시나리오:** NPC 여러 명의 턴은 이어 진행되지만 사용자의 반응 선택에서 멈춘다.
중단·재개가 기존 행동을 반복하지 않는다. 동일 초기 조건과 기록된 선택·주사위에서
상세 진행과 빠른 진행의 결과가 같고, 무한 진행은 한도로 차단된다.

### A5 일관된 장소와 탐험 상태

**플레이 가치:** 한 번 해결한 장치, 발견한 비밀 통로, 획득한 보물과 남은 자원이
재방문해도 유지되어야 탐험과 선택에 의미가 생긴다.

**참고 사례:** 연결된 방, 장치, 단서, 적, 보상과 유한한 자원을 가진 장소를
준비하고 방문·해결·보상 수령 상태를 갱신한다.

**도입 제안:** 장소를 유지되는 게임 대상으로 다루고, 이동·관찰·조사·상호작용을
구분한다. 지도와 조건을 준비한 뒤 여러 해결법을 허용한다. 미발견 정보의 노출 범위와
재방문·분기 시 상태를 정의한다. 생성 장소와 수작업 장소는 같은 실행 경로를 사용한다.

**수용 시나리오:** 보물과 자원은 중복 획득되지 않는다. 해결한 장치와 발견한 통로가
재방문에 유지된다. 다른 접근법도 판정할 수 있으며, 관찰 화면에 미발견 비밀이
노출되지 않는다.

## B 기존 판정 원칙을 유지할 도입 후보

| ID | 기능과 플레이 가치 | 도입 범위와 수용 시나리오 |
| --- | --- | --- |
| B1 | **판정·피해·보상 카드.** 결과와 원인을 즉시 이해한다. | 저장된 판정과 전후 변화를 표시한다. 과거 카드가 현재 HP 때문에 바뀌지 않고, 다시 표시할 때 판정을 실행하지 않는다. |
| B2 | **현재 장면 인물 보드.** 많은 등록 인물 중 현재 참가자를 파악한다. | 전체 인물과 장면 표시를 분리하고 전투·선택 대기 상태를 보여준다. 화면에서 숨기는 것과 세계에서 제거하는 것, 지식 접근 권한을 구분한다. |
| B3 | **관계·호칭·친숙도 기록.** 유명인 인지를 친분으로 오인하지 않는다. | 직접 만남·간접 인지·평판·모름·미확인과 방향별 호칭을 문맥에 반영한다. 미기록을 친분의 증거로 취급하지 않는다. 비밀 접근의 강제 차단은 별도 설계다. |
| B4 | **기억 검토·정정 화면.** 잘못된 기억을 고치며 캠페인을 유지한다. | 원문, 현재 기억, 수정 이력과 확인 대기를 연결한다. 정상 항목을 살리고 문제 항목만 보류한다. 보류된 항목은 검색·주입에 사용하지 않는다. |
| B5 | **룰·수치의 출처와 추정 표시.** 판정을 설명하고 하우스룰을 조정하기 쉽다. | 원문 명시·계산·추정을 작성 화면과 상세 정보에 구분한다. 근거 없는 계산을 원문 확정값으로 표시하지 않는다. A2의 작성 지원과 함께 다룰 수 있다. |
| B6 | **서술과 판정의 불일치 검사.** 실패를 성공으로 쓰거나 보상을 꾸미는 오류를 찾는다. | 우선 탐지·알림·서술 수정으로 한정한다. 사실 변경이 필요하면 A3의 GM 정정으로 연결한다. 검사 자체는 굴림·보상을 실행하지 않는다. |

## 도입 순서 제안

1. **빠른 체감 개선:** B1·B2로 판정과 현재 장면을 읽기 쉽게 만든다.
2. **TRPG 자유도 확장:** A1과 A3의 판정·정정 의미를 먼저 설계한다. A2·B5로
   설정을 플레이 자료로 만드는 작성 흐름을 연결한다.
3. **진행과 탐험 확장:** A4의 선택·중단·재개 경계, A5의 장소 수명과 정보 공개를 정한다.
4. **장기 플레이 품질:** B6의 불일치 검사와 B3·B4의 기억 활용·정정 경험을 보강한다.

위 순서는 제품 가치에 따른 제안이며 일정이나 저장소의 P0–P4 우선순위를 변경하지 않는다.
기억 UX 검토는 별도로 진행할 수 있다. B6는 A3 없이 탐지 기능부터 만들 수 있고,
A5는 A2의 자동 생성 없이 수작업 장소부터 시작할 수 있다.

## NMOS 기존 기능과의 관계

로컬 NMOS 기본 체크아웃 `556dab6`에는 지식 범위, 관계 이력, 사실 정정과 설정 고정의
설계·구현이 있다. B3·B4를 새로운 기억 엔진 전체를 만드는 과제로 해석하지 않는다.
친숙도의 표현, 부분 실패의 표시, 원문에서 정정까지의 사용자 흐름 중 실제 부족한
부분을 먼저 비교한다. 이 체크아웃만으로 진행 중인 다른 브랜치의 기능을 판단하지 않는다.

2026-10-09 Linear에서 확인한 기존 작업:

- [AGE-39 Inspector 기억 타임라인](https://linear.app/sallos725/issue/AGE-39)은
  인물 개요·포커스·현재 장면 필터를 다룬다. 인물 관계 격자 UI는 해당 작업에서 이미
  폐기했으므로 새 검토가 그 결정을 되돌리지 않는다.
- [AGE-2 상태와 관계 전이 및 충돌 큐](https://linear.app/sallos725/issue/AGE-2)는
  1.0 이후 보류 범위다. B4의 참고 검토가 이 작업의 재개나 출시 일정 변경을 뜻하지 않는다.

## 출처 기록 범위

참고 대상은 소유자가 제공한 외부 RisuAI TRPG·기억 플러그인이다. 공개 배포 중인
개인 제작물이므로 이 저장소에는 제품명, 파일명·해시, 내부 위치와 오프라인 실행 결과를
기록하지 않는다. 위의 관찰은 특정 버전의 모듈 수준 검토이며 실사용 품질을 보장하지 않는다.

플러그인 전체의 재사용 라이선스는 확인되지 않았다. 구현 아이디어를 참고하는 것과
원본 코드·룰·이미지를 복사하는 것은 구분하고, 복사가 필요하면 작성자의 조건을 별도로 확인한다.

## 후속 작업의 결정 지점

- A1: GM이 정할 수 있는 판정 조건, 자동 성공 기준, 추가 선택이 필요한 상황.
- A2: 누락값 추정 범위, 작성 자료의 확정 시점, 동일 인물·다중 개체의 식별.
- A3: GM 권한, 자동 정산 범위, 소급 정정과 대안 분기의 후속 사건 처리.
